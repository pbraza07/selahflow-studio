# v1.3.218 implementation and verification

## Scope

The release improves shared typography/wrapping, table containment, form sizing, focus indicators and modal sizing. Owner navigation exposes Bookable sessions, Team management and Payment setup directly while retaining every original destination and the existing unsaved-settings guard. Dashboard metrics open appointments, the schedule or reports for the selected date. Pending requests appear before quick actions; empty request panels are compact. Owner dialogs contain keyboard focus, support Escape and restore the opener. Failed settings saves retain drafts and display a persistent error.

The public availability message now displays the configured interval instead of a code placeholder. Spanish and Portuguese catalogs include the new interface labels and corrected navigation terminology. Existing business themes, IDs, form values, calculation formulas, server authorization, API behavior, payment rules, emails, booking capacity and stored records are unchanged.

## Browser checks

Private-role screens were tested with the actual client components in an isolated browser harness. It uses synthetic records and intercepted API responses; all mutation requests return a controlled validation error. It does not connect to a live customer account. This is component/workflow verification, not authenticated production acceptance.

| Screen | Observed checks |
| --- | --- |
| Owner dashboard | Desktop and narrow widths from 320 to 1363 CSS pixels; direct task navigation, selected destination, mobile drawer, meaningful summary-card actions, 40-row appointment table, long names/descriptions, compact empty state, English/Spanish/Portuguese layouts. |
| Owner booking/session settings | Dialogs fit phone viewports, long service descriptions scroll internally, notification bell stays behind the modal, close/Escape restores focus, native session editor remains in view, failed save preserves the session draft and capacity 17. |
| Owner settings | Failed save keeps entered business text; cancellation of the unsaved-navigation prompt keeps the current form. |

Measured document width equaled scroll width in the inspected cases. Wide owner tables scroll within their containers (for example a 791-pixel table inside a 326-pixel phone region). An early mock-provider error in the admin harness was corrected in the fixture; no new application-origin console error appeared in the subsequent inspected interactions. Browser extension messages were excluded.

Hosted English/Spanish/Portuguese controls and public navigation were inspected; no application-origin console errors were observed. No error-level startup entries were returned in the checked final staging and production windows. The refreshed production homepage shows v1.3.218, has no measured horizontal overflow at desktop width, and produced no observed application-origin console errors.

The default dark-green/white and dark-green/cream color pairs calculate to 11.68:1 and 10.63:1 contrast respectively; this is not an audit of every saved tenant palette.

## Limits

No real customer record, charge, outgoing notification, waiver signature or business-setting change was created for QA. Live Stripe onboarding/checkout, email delivery and authenticated hosted owner/team/admin acceptance were not exercised. Physical phones/tablets and actual browser-zoom controls were not tested; narrow CSS viewports tested reflow. Not every screen, tenant palette, long-content combination or translation sentence has been exhaustively reviewed. Translation packs still contain earlier machine-prepared text; custom business content, PDFs, emails, native apps and external provider pages retain their original language.
