# SelahFlow v1.3.222 verification

## Change

Owners can select **Override weekly session limit** for an individual member under Memberships/Packages → Member enrollments → Sessions used. It saves immediately, defaults to off, and can be turned off again. Plans without a weekly allowance show a disabled checkbox and explanatory text. The existing four-column membership table is retained, with English, Spanish and Portuguese copy.

The owner-only API validates the member, business and boolean value, holds the business schedule lock, and records an audit event. The setting bypasses only the selected member's weekly count. Paid dates, membership-month credit allocations, pending reservations, used sessions, service eligibility, approval and capacity checks remain authoritative.

Server-issued, business/member/date-bound admission records let already accepted sessions retain attendance eligibility after the override is turned off. New scheduling once disabled follows the weekly cap and cannot create a second monthly allowance on top of prior override bookings. Public input cannot issue admission records. Late attendance updates its original credit period once, preserves current-month credits, and handles legacy archived timestamps without summing duplicate snapshots. Additive migration 094 preserves existing members, plans, payments and session history.

## Checks

UI tests cover the per-member request, saved refresh, restoring the limit, accessible naming, disabled nonweekly plans, unchanged table columns, saving state, failure behavior, stale polling and actual Portuguese translation. Booking integration tests cover approval, distinct pending and appointment identifiers, forged overrides, capacity, paid dates, service eligibility, competing reservations, same-date rescheduling and date-bound admission proofs.

An actual rendered membership component was inspected in a hosted browser at desktop and 375-pixel phone widths. The translated Portuguese checkbox, helper, enabled state and disabled nonweekly state remained readable in the horizontally scrollable table. Synthetic members were used; no real member settings, bookings, messages or payments were changed for QA.

Full regression, production build, hosted validation and exact LIVE deployment results are pending. Authenticated hosted owner editing was not manually exercised; endpoint and component behavior are tested with isolated fixtures.
