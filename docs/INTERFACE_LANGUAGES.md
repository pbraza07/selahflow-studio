# Interface languages

The root layout includes a shared, accessible flag selector: en-US (United States), es-ES (Spain), pt-BR (Brazil). English is the default. Device storage remembers the choice across navigation and synchronizes it across tabs. Blocked storage does not prevent switching in the current page.

The Spanish and Portuguese catalogs are same-origin static JSON files loaded only when selected. They contain more than 6,000 source strings each. The initial packs were prepared offline from source interface copy with the Argos-compatible en-es and en-pt CTranslate2 models, then curated for principal navigation, payments, memberships and Brazilian usage. Models are build-time preparation tools, not application dependencies. No model or translation provider is called by the running application. Language packs contain no records from the database.

`server/page-translation.mjs` updates existing text node data and display-only attributes, preserving React ownership, handlers, input values, selection values, URLs, IDs and canonical records. It observes newly rendered dialogs, statuses and route content; native confirmation messages use the same catalog. English restores the most recent source text, including text React changed while another language was selected. Inline name/contact displays are marked `translate="no"` so a client named May is not displayed as a month. Custom business content without a catalog match remains as entered. Editable content, source code and explicit `translate="no"` regions are excluded. PDFs, transactional emails, the separate native payment app and external payment-provider pages are outside this web-interface selector.

To maintain a release, run `node scripts/extract-ui-copy.mjs` to list source candidates and interpolation templates in temporary JSON files (or pass output paths). Review candidates: extraction can include technical literals that should not become translations. Add matching keys to both packs, preserve all numbers, provider names and `{0}` style slots, and review payment/consent wording. Keep preferred terms in `scripts/translation-overrides.json`; `node scripts/apply-translation-overrides.mjs` reapplies them. Unknown strings intentionally retain English rather than guessing. Human language review of every machine-prepared sentence has not been completed.

Run `node --test tests/page-translation.test.mjs` plus the full regression/typecheck/build checks. Interaction coverage uses the actual React renderer and DOM observer, including state updates, conditional node removal/recreation, forms, asynchronous dialogs, return to English and native confirmation cleanup.
