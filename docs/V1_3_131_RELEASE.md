# v1.3.131 — green, editable owner checkbox controls

The circled Service catalog approval boxes now use green, interactive controls and save true or false instead of being disabled and forcibly reset by the server. Services without an explicit value retain approval-required behavior. Only new bookings for explicitly unchecked services confirm immediately; mixed-service visits require approval if any selected service requires it. Existing pending requests stay pending. Notification routing remains independent.

Direct public confirmations recheck approval configuration, current service quote, waiver, membership eligibility and capacity under the same business schedule lock; coupons are calculated transactionally, preserved on the appointment and reflected in the receipt/payment invitation queues. Secure links and message deduplication use the existing delivery path. Owners must save settings to publish changes.

Questions → Required is now editable for first name, last name and birth date, as for all other standard/custom questions. Explicit service/session false overrides are honored. Multi-service visits take the union of service requirements. Optional incomplete booking identities receive no fabricated Unique ID. Complete identities still use initials + MMDDYY and retained identity/consent/deletion rules. Waiver-enabled services still need valid identity-linked signed consent; making a form answer optional does not bypass an enabled waiver. Membership identity/payment validations still apply when allocating an ID or starting a subscription.

Session automatic-host checkbox is editable and represents the explicit preference; hidden hosts remain privately assigned for client privacy. Default accountability host checkbox is editable using trackSessionHost:false, independent of actual scheduling host/capacity; recurrence inherits the setting. Owner Calendar can still explicitly assign anyone or leave accountability unassigned. Public catalogs omit private tracking flags/IDs.

Audit of all JSX checkbox inputs: no permanently disabled owner configuration checkbox remains. Temporary busy/loading safeguards in owner History, Reports and Calendar assignments, the History 500-selection batch limit, and platform administrator primary/active-business eligibility remain enforced. Enabled native checkboxes use green across the app and palettes with keyboard focus outlines. Public signature/payment consent and authorization boundaries remain intact. Unchecking All services/sessions narrows a question to the current selected catalog rather than silently ignoring the click.

Verification pending. No migrations, environment/provider changes, real customer messages, bookings, charges, deletions or business preference changes for QA. Automated regression tests use synthetic PostgreSQL records and component handlers. Actual signed-in owner browser/mobile acceptance has not been performed.
